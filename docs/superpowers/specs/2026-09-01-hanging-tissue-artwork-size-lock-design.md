# 悬挂抽纸贴图尺寸锁定设计

## 目标

悬挂抽纸四面图片上传完成后，调整盒身宽度、高度或厚度只能改变模型几何；图片的显示比例、物理显示大小、旋转和偏移不得随盒身尺寸变化。

## 已确认行为

- 每张图片上传时记录当时的盒身宽度、高度和厚度，作为该面的贴图尺寸基准。
- 正面和背面的物理显示尺寸以基准宽度、基准高度锁定。
- 左侧和右侧的物理显示尺寸以基准厚度、基准高度锁定。
- 盒身变大后，图片保持原大小，新增区域显示白色。
- 盒身缩小后，图片保持原大小，超出当前盒面的区域被裁切。
- 重新上传某一面图片时，只刷新该面的尺寸基准。
- 删除图片时一并删除该面的尺寸基准。
- 现有每面缩放、偏移、旋转、横向拉伸和纵向拉伸继续以锁定后的图片为基础生效。

## 状态与兼容

`HangingTissueState` 增加四面独立的 `artworkReferenceDimensions`。每项保存上传时的 `width`、`height` 和 `depth`。

项目格式版本递增。旧项目没有尺寸基准时，迁移过程使用文件中当前悬挂抽纸尺寸为所有已上传面的基准；未上传面保持空基准，因此打开旧文件后画面不跳变。

## 纹理计算

现有 atlas 绘制继续先按图片原始比例和用户变换计算。绘制到目标 UV 岛前再应用盒身尺寸反向补偿：

- 正背面横向补偿：`reference.width / current.width`。
- 左右面横向补偿：`reference.depth / current.depth`。
- 四面纵向补偿：`reference.height / current.height`。

反向补偿只改变 atlas 中图片占用范围，不修改模型 UV、图片资源或用户可见的变换数值。UV 岛裁切和岛外白色背景保持现有行为。

## 完成标准

1. 上传图片后分别改变宽度、高度和厚度，图片的物理显示大小和比例保持不变。
2. 正背面不受厚度变化影响，左右面不受宽度变化影响。
3. 盒身变大出现白色余量，盒身变小裁切超出内容，不拉伸图片。
4. 每面重新上传后以新的当前盒身尺寸建立基准，其他面不受影响。
5. 旧项目迁移后首次显示不发生跳变，保存与重新打开结果一致。

## 验证

- 纹理单元测试覆盖正背和左右两套反向补偿比例。
- reducer 测试覆盖上传、替换和删除时的独立基准变化。
- codec 测试覆盖旧版本迁移和新版本往返保存。
- 运行悬挂抽纸相关测试、类型检查、lint 和生产构建，并做一次宽高厚代表性浏览器检查。
