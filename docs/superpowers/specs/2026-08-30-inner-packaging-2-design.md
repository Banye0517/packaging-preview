# 内包装2设计

## 目标

新增独立盒型“内包装2”，使用用户提供的 `翅中.gltf` 原始模型和 `未标题_1.psd` UV 参考。用户分别上传正面、背面设计图，图片在模型对应表面实时显示并可独立调整。

## 已确认范围

- 保留模型原生几何、厚度、圆角、鼓起和原生 UV，不用现有自立袋或内包装1的几何替代。
- PSD 左侧 UV 岛是正面，右侧 UV 岛是背面。
- 正面和背面分别上传 PNG、JPG 或 WebP；未上传面保持白色。
- 每一面独立支持 50%–300% 等比缩放、-100%–100% 水平/垂直移动、-180°–180°旋转和重置。
- 图片保持原始宽高比，不提供水平或垂直拉伸，不平铺，不拉伸边缘。
- 复用内包装1的袋宽、袋高和 0°/90°/180°模型方向控制。
- 内包装2不支持表面工艺。本次不改变六面盒、自立袋和内包装1的配置或行为。

## 模型和贴图架构

将 `翅中.gltf` 复制为项目内固定模型资源。渲染组件读取唯一主网格，应用节点世界变换后按内包装1现有规则拟合用户设置的宽高，并保持模型原生深度和外形比例。

贴图生成使用 1024×1024离屏画布，并保留 glTF 原生 UV：画布左半区绘制正面，右半区绘制背面。每一面先在自己的 512×1024局部坐标中完成等比缩放、位移和旋转，再裁切到所属半区，确保一面的图片不会越界污染另一面。画布底色始终为白色。

模型、PSD 和代码约定共同固定“左半区为正面、右半区为背面”。首次实现必须用不同颜色的正背测试图在真实 3D 模型上验证方向；如果 glTF 采样方向存在上下或水平翻转，只在贴图合成映射层修正，不修改用户图片、不重建 UV。

## 状态与交互

项目状态新增 `innerPackaging2`，包含：

- `faces.front`、`faces.back`
- `transforms.front`、`transforms.back`
- `width`、`height`
- `modelRotation`

盒型切换增加“内包装2”。贴图页显示正面、背面两个上传卡片；选择某一面后只显示和修改该面的贴图变换。盒型页显示与内包装1一致的宽高和模型方向控制。保存、打开、新建、撤销、重做和透明 PNG 导出继续走现有项目状态与场景流程。

项目文件版本递增。旧版本加载时补齐默认空白 `innerPackaging2`，不改变旧项目当前盒型和已有资源。

## 错误处理

沿用现有图片类型、尺寸和解码校验。不支持或损坏的文件只在对应面显示错误，不替换原有有效图片。模型找不到唯一主网格、缺少 UV 或 UV 超出预期左右区域时，测试和开发环境明确失败，避免静默显示错误映射。

## 验收标准

- 盒型列表出现“内包装2”，切换后显示提供的翅中模型。
- 贴图页只有正面、背面两个上传入口。
- 正面图片只显示在 PSD 左侧 UV 对应的模型正面；背面图片只显示在右侧 UV 对应的模型背面。
- 两面变换完全独立，旋转、缩放和移动时图片不形变、不跨面、不平铺。
- 宽高和模型方向行为与内包装1一致，模型厚度、圆角和鼓起形态保持。
- 六面盒、自立袋、内包装1及其工艺功能不回归。
- reducer、codec、上传面板、UV合成和模型资源测试通过；类型检查、lint、完整测试、生产构建、Sites测试通过。
- 在真实浏览器分别上传高对比正背测试图，旋转模型检查正背方向、白色未覆盖区和变换结果；桌面布局无额外页面滚动区域。

## 风险与取舍

保留原生 UV 能最准确贴合圆角和鼓起表面，但正反面必须合成到同一张纹理。分半区裁切是最小且可靠的边界，代价是每一面只能使用纹理宽度的一半；1024×1024画布对当前实时预览足够，后续若导出清晰度不足，应统一提高合成纹理分辨率，而不是改变 UV。
