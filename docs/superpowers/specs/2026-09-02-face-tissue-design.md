# 面纸盒型设计

## 目标

在现有“包装预览”中新增“面纸”盒型：用户只上传一张按所给 UV 展开的完整图稿，即可覆盖面纸主体的前、后、上、下区域；左右侧面保留模型结构材质。面纸主体支持宽、高、厚度调整，顶部抽纸支持显示/隐藏，图稿支持复用悬挂抽纸的高级微调能力。

## 已确认的输入事实

- 模型来源：`/Users/banye/Downloads/面纸/面纸.gltf`。
- UV 参考：`/Users/banye/Downloads/面纸/未标题_4.psd`，为 1024×1024 的完整 UV 展开参考。
- 单张图稿覆盖前、后、上、下，不覆盖左右侧面。
- `面纸.gltf` 包含三个网格：`Default`、`Default-材质.2`、`纸`。
- 几何数据表明 `Default` 主要由前/后/上/下方向面组成，`Default-材质.2` 主要由左右方向面组成；`纸` 是独立顶部抽纸节点。
- 顶部抽纸默认显示。

## 范围

### 包含

- 新增包装类型 ID：`face-tissue`，显示名“面纸”。
- 单张 artwork 上传、替换、删除。
- 使用模型原生 UV 直接映射完整图稿，不在首次上传时要求用户校准。
- 图稿变换：比例缩放 50%–300%、水平/垂直位置 -100%–100%、旋转 -180°–180%、水平/垂直拉伸 50%–300%；高级区域默认收起。
- 面纸主体宽、高、厚度输入，底部保持接触地面。
- 模型方向 0°/90°/180°。
- 顶部抽纸显示/隐藏开关，默认显示。
- 旧项目 codec 迁移：旧文档补充默认面纸状态，不影响其他盒型。
- 复用现有悬挂抽纸的变换控件和通用 artwork 读取逻辑。

### 不包含

- 面纸左右侧面的图稿上传。
- 面纸工艺层、工艺蒙版或表面效果。
- PSD 解析、自动切图、刀模识别或自动分配。
- 改动悬挂抽纸既有行为。
- 新增“场景”或“AI”设置区。

## 推荐方案

保留 GLTF 原生 UV，并按网格职责分离材质：

1. 克隆并渲染 `Default` 主体网格。上传图稿时创建 direct-color artwork material，使用 `MeshBasicMaterial`、纯白底色和 `toneMapped={false}`，确保图稿颜色不被场景灯光改变。
2. 克隆并渲染 `Default-材质.2` 侧面网格，使用物理受光的白色 `MeshStandardMaterial`，不挂载用户图稿。
3. 克隆独立 `纸` 节点，使用与主体结构一致的白色受光材质；只通过 `showTopSheet` 控制可见性。
4. 图稿变换只作用于 artwork canvas 的绘制矩阵，不改 UV 和模型结构；未覆盖区域保持白色主体材质。
5. 尺寸调整只对面纸主体几何做以底部为锚点的轴向变形；顶部抽纸保持独立节点，位置随主体顶部更新，避免尺寸变化后与开口脱离。模型方向在外层 group 上旋转。

该方案直接使用用户已提供的 UV 展开，能保留前/后/上/下之间的连续关系，也能天然隔离左右侧面，是满足“上传即贴合”的最短路径。

## 状态与数据流

新增 `FaceTissueState`，字段如下：

- `artwork: ArtworkAsset | null`
- `width: number`
- `height: number`
- `thickness: number`
- `artworkTransform: ArtworkTransform`
- `modelRotation: 0 | 90 | 180`
- `showTopSheet: boolean`

新增 reducer action 命名空间 `face-tissue/*`，包括 artwork set/remove、transform set/reset、rotation set、dimension set、top-sheet visibility set。

上传流程沿用现有 `ArtworkAsset` 和图像校验规则。上传完成后只写入 artwork，不自动修改变换字段；由于原生 UV 与完整 UV 图稿是一一对应的，默认变换为 100%、0%、0%、0°、100%、100%。

## UI

- 盒型选择器新增“面纸”。
- 贴图区显示一个上传卡片，文案明确为“面纸图稿（完整 UV）”，不显示四面上传网格。
- 高级调整默认收起，展开后显示六个变换控制项及“重置”。
- 盒型区显示宽度、高度、厚度，以及模型方向控制；不显示左右面上传或工艺控制。
- 贴图区显示“顶部抽纸”开关，默认开启。
- 保持桌面左侧固定 3D 预览、右侧设置区独立滚动；移动端继续使用现有堆叠布局。

## 模型与变形边界

- 新资产存放为 `public/models/face-tissue.gltf`，内容来自用户提供的 `面纸.gltf`。
- 只把 `Default` 作为可印刷主体；`Default-材质.2` 是侧面结构；`纸` 是独立显隐节点。
- 不通过法线重建平面 UV，不重排用户提供的 UV。
- 主体宽、高、厚度使用模型初始包围盒作为基准比例；变形结果重新计算法线、包围盒和包围球。
- 变形后的主体底部对齐现有场景接触地面；抽纸节点保持其原始形状，并随主体顶部定位。
- 无 artwork 时主体、侧面和抽纸全部保留受光白色材质；有 artwork 时只有 `Default` 使用 direct-color artwork 材质。

## 兼容与迁移

- `ProjectState.version` 递增一个版本。
- `createInitialProject()` 生成默认面纸状态，默认尺寸沿用面纸模型基准映射，`showTopSheet: true`，变换为默认值。
- `decodeProject()` 为所有旧版本补齐面纸状态；旧项目的盒型、贴图、工艺和相机状态保持不变。
- 面纸不参与 box finish 或 pouch finish 状态，避免新增不支持的工艺路径。

## 验证与验收标准

自动化测试至少覆盖：

- 包装类型和默认状态初始化。
- 旧版本 codec 迁移及默认抽纸显示。
- artwork 上传、删除、变换范围、变换重置、尺寸输入和模型方向。
- 顶部抽纸显隐 action 只影响 `纸` 节点。
- GLTF 资产存在、节点名称和 UV 存在。
- `Default` 使用 artwork、`Default-材质.2` 保持白色受光材质、`纸` 保持独立材质。
- 主体变形底部锚定，变换不会重建或覆盖 UV。

## 风险与处理

- 如果实际上传的图稿不是按该 PSD 的同一 UV 画布导出，原生 UV 无法替用户推断版面；UI 会明确提示“请上传完整 UV 图稿”。
- 如果面纸模型在不同 GLTF loader 版本中对节点变换有差异，模型基准尺寸和抽纸定位需要通过浏览器实物检查校正；不改变用户变换值。
- 面纸不提供工艺能力是有意限制，避免把只有前后/主体印刷的模型误接入六面工艺流程。
