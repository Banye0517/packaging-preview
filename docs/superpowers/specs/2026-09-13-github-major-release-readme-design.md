# GitHub 大版本首页与截图设计

## 目标

将当前包装预览大版本更新到 GitHub，并让仓库首页同时传达两件事：它能产出具有展示质量的 3D 包装组合图，也具备面向包装设计师的完整工作流能力。

## 发布范围

- 更新 GitHub `main` 到本地已验证版本。
- 重写 `README.md` 的产品结构与大版本功能说明。
- 新增 1 张主视觉和 3 张功能截图，全部来自当前真实应用。
- 保留在线演示、许可证与素材授权说明。
- 不修改产品功能、不发布新的 Sites 版本、不加入 GIF 或大体积视频。

## 首页结构

1. 标题、中文定位、在线演示入口与核心能力摘要。
2. 一张横向主视觉，展示多盒型、贴图、展台与成品构图。
3. “本次大版本更新”章节，说明组合、排列、物理尺寸、展台与出图系统。
4. 三张功能截图，每张对应一个清晰主题。
5. 完整功能清单、支持盒型、工作流、技术栈和本地运行方式。
6. 数据隐私、已知限制与许可证。

## 截图清单

### 01 主视觉

- 画幅：16:9。
- 内容：4–6 个不同或重复包装实例，使用带颜色的真实图稿，启用暖白或浅灰的一体式阶梯展台。
- 目的：第一屏直接体现这是一个可用于包装组合提案的工具。

### 02 多盒型组合与展台

- 展示实例列表、四种排列入口、展台类型、颜色和圆角控制。
- 3D 区域中至少出现三种盒型，前后层级清晰，无穿模、无悬空。

### 03 独立贴图与尺寸

- 展示选中单个实例后的贴图或盒型设置。
- 强调同类包装可以重复添加，并各自拥有独立图稿、尺寸和状态。

### 04 固定取景框与导出

- 展示 1:1、16:9、9:16 选择、框外工具栏和白色导出范围。
- 模型可以超出取景框，控件不能遮挡白框，画面需能明确理解实际导出裁切。

图片统一保存到 `docs/images/`，使用语义化英文文件名和经过压缩的 WebP；README 使用仓库相对路径，确保 GitHub 首页直接显示。

## 大版本功能叙事

README 重点说明：

- 支持 1–6 个独立包装实例，可混合不同盒型，也可重复同一盒型。
- 每个实例独立保存图稿、尺寸、工艺和模型状态。
- 2–6 个实例提供 A/B/C/D 四种排列，并按数量推荐默认方案。
- 按真实世界包围盒计算间距，自动防穿插、落地、居中和相机适配。
- 一体式展台支持关闭、三种造型、五种颜色和 0–30 mm 圆角。
- 后排根据三种导出画幅的最差遮挡结果自动升高，切换比例不改变模型站位。
- 固定取景框支持 800×800、3000×3000、2560×1440 和 1440×2560 PNG。
- 保留盒型贴图、表面工艺、灯光、项目保存/打开和透明 PNG 导出能力。

## 验收标准

- 四张图片均来自当前真实应用，没有概念图或伪造界面。
- 主视觉能够在 GitHub README 常见宽度下辨认包装组合和展台。
- 每张功能截图只承担一个主题，没有菜单遮挡、文字截断或白框错位。
- README 中所有本地图片路径、在线演示链接和章节锚点可用。
- `npm test -- --run`、`npm run typecheck`、`npm run lint`、`npm run build` 和 `npm run test:sites` 通过。
- 推送后用 `git ls-remote` 验证 GitHub `main` 精确指向本地提交，并打开 GitHub 首页确认图片真实加载。

## 风险与控制

- 截图如果使用空白模型会削弱可信度，因此优先复用项目中可合法展示的现有图稿；若没有合适素材，使用简单自制色块图稿而不是外部未授权图片。
- 3D 截图和原尺寸 PNG 可能使仓库膨胀，统一使用 WebP 并控制单张文件体积。
- 推送只面向 `github` 远端的 `main`，不改动内部 `origin`。
- 保留工作区中与本次发布无关的未跟踪文件，不纳入提交。
